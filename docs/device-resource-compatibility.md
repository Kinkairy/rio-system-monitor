# 屏内存储兼容性实测

2026-10-23，设备为 WinUSB `2A55:9990`、USB revision `0200`、LCD 480×480。本次在用户明确允许覆盖默认动画后进行测试。程序停止实时输出并释放句柄，由单一会话按资源白名单发送命令，没有运行原厂程序。

| 步骤 | 设备返回 | 结论 |
| --- | --- | --- |
| `CD 00 00 00 00 03 …`，tag 1，读 5 字节 | `e001e001ff`；CSW `55534253010000000500000000` | 尺寸为 480×480，tag 1，status 0 |
| `FB D8 00 …`，资源偏移 0，tag 2 | CSW `55534253010000000500000002` | 仍返回 tag 1，status 2；没有确认擦除 |
| GIF 数据写入 `FB D9` | 没有发送 | 首条擦除失败即停止 |
| 播放新资源 | 没有发送 | 未将失败当作成功 |

首次测试擦除确认数为 0，写入确认数为 0。不能把该异常当作成功，也不能通过忽略 tag/status 校验继续。测试后重新启动主程序，实时帧收到成功应答且 USB 无错误；回包本身不代替实际画面验收。完整 USB 应答和默认动画 SHA-256 只保存在本地验证记录，不公开素材或 EXE。

## 查询后等待一秒的复核

静态参考软件在设备查询之后等待约一秒，原实现查询成功后立即发送首条擦除命令。本机在保持相同资源命令、目标范围、默认动画及严格状态校验的情况下，仅在查询成功之后、首条擦除之前加入一秒等待，完成了整份默认动画的上传：

| 步骤 | 确认结果 |
| --- | --- |
| 默认 GIF | 1,022,714 字节，480×480，216 帧 |
| 资源擦除 | 250 / 250 个块应答成功 |
| 数据写入 | 250 / 250 个块应答成功 |
| 结束命令 | tag 与 status 校验通过 |

等待发生在后台存储线程，设备身份和尺寸核验成功之后、使旧预览记录失效之前；不会阻塞设置界面，也不会在查询失败时擦写。没有放宽命令白名单、地址边界或异常停止规则。新增回归测试约束查询、等待、缓存失效和首条擦除的先后顺序。

这次已确认完整上传。随后正常退出主程序并停止实时输出，用户拔下 USB 再插回，明确确认屏幕自动播放新的彩色 RIO 启动动画，完成本机默认动画的断电持久播放验收。USB 文件回读仍未实现。

现有参考 EXE 中可以定位 FBD8 擦除、FBD9 写入与 FBDA 配置写入流程，尚未找到可验证的图片资源回读流程。此前只读 SPI/Flash 查询未返回有效文件数据。标准 dpf-ax 提供 Flash 读取 API，但其[Windows 原厂固件读取工具](https://github.com/dreamlayers/dpf-ax/blob/master/tools/readflash_win.py)要求设备以 CD-ROM 方式连接，不能直接当作本机 WinUSB 模式的兼容性证明。

文件预览缓存仅代表本程序最后一次完整成功写入的记录，不是屏内文件的 USB 回读。资源上传、用户确认的断电持久播放和尚未实现的文件回读分别记录。
